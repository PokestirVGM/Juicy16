# Host test protocol

Phase 7 of [../MILESTONE_PLAN.md](../MILESTONE_PLAN.md) requires the same MIDI
coverage the offline suite proves, run again *through a real DAW*, on every
supported host and platform. This document is how that session is run: the
fixtures to import, the exact value expected at every step, and a results table
to fill in.

Everything here is designed so a step has one unambiguous answer. If an
observation does not match, the plugin or the host is at fault — not the fixture,
because the fixtures are validated offline by `engine_host_program_matrix` and
`engine_host_controllers` on every CI run before anyone imports them.

## Fixtures

| File | Purpose | Length |
| --- | --- | --- |
| [../tests/fixtures/host/host_program_matrix.mid](../tests/fixtures/host/host_program_matrix.mid) | 16 independent Program Changes at three checkpoints | 24 s |
| [../tests/fixtures/host/host_controllers.mid](../tests/fixtures/host/host_controllers.mid) | CC, pitch bend, RPN, pedals, channel mode | 36 s |

Both are original General MIDI content, generated by
`tools/make_host_fixtures.py` and freely redistributable. The private game rip in
`testfiles/` is **not** redistributable and is not part of this protocol; it
remains the extra real-world pass in Phase 7.1.

Both files are 120 BPM in 4/4, so **one bar is exactly 2 seconds** and bar *n*
starts at `(n-1) x 2` seconds. Every step carries an SMF marker, so the DAW's
marker track names each step as it plays.

## Setting up an instance

1. Start from a **new empty project**. A carried-over project defeats the point:
   Phase 7 requires a fresh instance with no manual channel assignments.
2. Insert one Juicy16 instance. Note the format (AU or VST3) and the exact host
   version — both go in the results table.
3. Load a bank. Use the system GM bank so program numbers mean what this document
   says they mean:
   - macOS: `/System/Library/Components/CoreAudio.component/Contents/Resources/gs_instruments.dls`
   - Windows: `C:\Windows\System32\drivers\gm.dls`
4. Import the fixture and route it so that **all 16 channels reach that one
   instance**. This is the step hosts get wrong, and it is host configuration
   rather than a plugin defect — but it must be confirmed before anything below
   means anything:
   - **Cubase**: import as a single MIDI track and set the track's MIDI channel
     to *Any*. If Cubase offers to split the file into one track per channel,
     decline, or route every resulting track to the same instrument.
   - **FL Studio**: the plugin must receive all channels rather than one per
     instance; check the channel/port assignment in the plugin wrapper settings.
   - **Logic**: use a multi-timbral instrument setup so channels are not
     collapsed to 1.
5. Do **not** touch the instrument dropdowns at any point. The fixture alone must
   drive every instrument.

## Test A — 16-channel Program Change matrix

Play `host_program_matrix.mid` from the start. At each checkpoint the file sends
Bank Select 0 plus a Program Change on all 16 channels, then a note on the *same
tick* (which must already use the new program), then a second note two beats
later.

Read the plugin's own 16-row channel list at each checkpoint and compare. Program
numbers are shown 1-based, as the plugin and most DAWs display them.

| MIDI ch | Checkpoint A (bar 1, 0 s) | Checkpoint B (bar 5, 8 s) | Checkpoint C (bar 9, 16 s) | Note |
| --- | --- | --- | --- | --- |
| 1 | 1 Acoustic Grand Piano | 5 Electric Piano 1 | 1 Acoustic Grand Piano | 60 |
| 2 | 12 Vibraphone | 15 Tubular Bells | 12 Vibraphone | 64 |
| 3 | 20 Church Organ | 22 Accordion | 20 Church Organ | 67 |
| 4 | 25 Acoustic Guitar (nylon) | 31 Distortion Guitar | 25 Acoustic Guitar (nylon) | 72 |
| 5 | 34 Electric Bass (finger) | 39 Synth Bass 1 | 34 Electric Bass (finger) | 36 |
| 6 | 41 Violin | 43 Cello | 41 Violin | 69 |
| 7 | 49 String Ensemble 1 | 53 Choir Aahs | 49 String Ensemble 1 | 62 |
| 8 | 57 Trumpet | 61 French Horn | 57 Trumpet | 65 |
| 9 | 66 Alto Sax | 72 Clarinet | 66 Alto Sax | 70 |
| 10 | drum kit (program 1) | drum kit (program 1) | drum kit (program 1) | 36, bass drum |
| 11 | 74 Flute | 76 Pan Flute | 74 Flute | 74 |
| 12 | 81 Lead 1 (square) | 88 Lead 8 (bass + lead) | 81 Lead 1 (square) | 76 |
| 13 | 89 Pad 1 (new age) | 96 Pad 8 (sweep) | 89 Pad 1 (new age) | 55 |
| 14 | 105 Sitar | 109 Kalimba | 105 Sitar | 59 |
| 15 | 113 Tinkle Bell | 120 Reverse Cymbal | 113 Tinkle Bell | 79 |
| 16 | 121 Guitar Fret Noise | 128 Gunshot | 121 Guitar Fret Noise | 61 |

Checkpoint C deliberately returns to checkpoint A's programs, so the file loops
cleanly and a stale-state bug shows up as C not matching A.

Channel 10 keeps program 1 throughout because which drum kits exist is
bank-dependent. Verify it by ear instead: it must sound as **percussion**, not as
a pitched instrument. A channel 10 that plays a piano note means the percussion
bank was lost.

### Required repeats

Run the whole file again after each of these, and confirm the same three
checkpoint columns:

- [ ] Stop and start from the beginning
- [ ] Rewind mid-playback
- [ ] Loop bars 1-8 (checkpoints A and B alternating)
- [ ] Start playback **at bar 5** with the host's chase/"send events on locate"
      enabled — the channel list must reach checkpoint B without ever having
      played bar 1
- [ ] Start playback at bar 9
- [ ] Save, close, and reopen the project
- [ ] Close and reopen the plugin window

### The FL Studio versus Cubase comparison

Phase 7 requires this comparison explicitly, because the two hosts drive Program
Change through different VST3 mechanisms — FL Studio via `IMidiMapping`, Cubase
via per-channel unit program parameters — and Juicy16 implements both.

Run test A identically in both. The checkpoint tables must be **identical**. A
result where FL Studio is correct and Cubase collapses to channel 1, or where any
host leaves only channel 1 responding, is a **B1 release blocker**: record it and
reject the candidate.

## Test B — controllers, pitch bend, pedals, channel mode

Play `host_controllers.mid`. **Select channel 1's row in the plugin** first: the
six sound sliders show the selected channel's controller values, which is how you
read exact numbers without an event trace.

| Bar | Time | Step | What must happen |
| --- | --- | --- | --- |
| 1 | 0:00 | SETUP - reset all 16 channels | All channels take a program; sliders sit at 64 |
| 2 | 0:02 | CC74 Filter cutoff 0-64-127 | The **Cut** slider moves to 0, then 64, then 127; the held note gets brighter |
| 3 | 0:04 | CC71 Filter resonance 0-64-127 | The **Res** slider moves to 0, 64, 127 |
| 4 | 0:06 | CC73 Attack 0-64-127 | The **Att** slider moves to 0, 64, 127; each retriggered note starts slower |
| 5 | 0:08 | CC75 Decay 0-64-127 | The **Dec** slider moves to 0, 64, 127 |
| 6 | 0:10 | CC79 Sustain level 0-64-127 | The **Sus** slider moves to 0, 64, 127 |
| 7 | 0:12 | CC72 Release 0-64-127 | The **Rel** slider moves to 0, 64, 127; tails lengthen |
| 8 | 0:14 | CC7 volume, then CC11 expression | Loud, half, quiet; then expression does the same |
| 9 | 0:16 | CC10 pan | Hard left, centre, hard right |
| 10 | 0:18 | CC1 mod, CC91 reverb, CC93 chorus | Each audibly engages then disengages (depends on the bank's modulators) |
| 11 | 0:20 | CC64 sustain pedal | A note released at beat 2 keeps ringing until the pedal lifts at beat 4 |
| 12 | 0:22 | CC66 sostenuto, CC67 soft | The note held when sostenuto engages keeps ringing; the *later* note does not. Soft pedal quietens the final note |
| 13 | 0:24 | BEND ch1 full down / centre / full up | Down a whole tone, back to pitch, up a whole tone (default range 2 semitones) |
| 14 | 0:26 | RPN 0,0 sets ch2 range to 12 | Channel 2 bends a **full octave** while channel 1, bending identically, moves only a whole tone |
| 15 | 0:28 | BEND ch10 and ch16, opposite bend on ch1 | Channels bend **independently** and in opposite directions at the same time |
| 16 | 0:30 | CC120 All Sound Off | All three sounding notes cut **instantly**, no release tail |
| 17 | 0:32 | CC123 All Notes Off, then CC121 Reset All Controllers | Notes stop; the **Cut** slider returns from 20 to 64 |
| 18 | 0:34 | TAIL | Silence |

Bar 14 is the important one for pitch bend: it proves the 14-bit range and
per-channel RPN bend ranges are both honoured, and it is self-checking because
channel 1 and channel 2 receive the *same* bend values.

### Host chase behaviour

Record any difference between what the fixture sends and what arrives as a
**host** characteristic, separately from plugin defects. Hosts legitimately
differ in whether they chase controllers and bends when playback starts
mid-song. Note per host:

- Does starting at bar 9 chase CC values, or do the sliders stay where they were?
- Does the host filter, normalise, or collapse any controller before it reaches
  the plugin?

## Test C — everything else per host/platform combination

- [ ] Load SF2, SF3, well-formed DLS, and a repaired DLS in turn
- [ ] Confirm channel 10 percussion (test A)
- [ ] Dense playback near the 512-voice ceiling
- [ ] Sample rates 44.1, 48, and 88.2/96 kHz where the host offers them
- [ ] Several buffer sizes
- [ ] Save, close, reopen; complete state restoration
- [ ] Send GM, GS, and XG resets followed by notes
- [ ] Confirm no crash or state corruption when the bank file is missing or invalid
- [ ] Resize the editor to minimum, default, and maximum
- [ ] Keyboard operation: Tab reaches the controls, arrows select a channel,
      Return opens that row's instrument list. **Report any host that swallows
      Tab before it reaches the editor** — that is a host characteristic, and it
      is the one keyboard question the offline suite cannot answer
- [ ] Screen reader (VoiceOver on macOS, Narrator on Windows): does each control
      announce a useful name and role? This has never been run

## Regenerating the fixtures

```bash
python3 tools/make_host_fixtures.py
```

The committed files must stay byte-identical to the generator's output;
`host_fixtures_reproducible` enforces that. The tables above are read off the
same source, so regenerating after a change to the generator means re-reading
them.
